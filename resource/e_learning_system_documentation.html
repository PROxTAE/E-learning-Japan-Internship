🎓 ระบบคืออะไร

Interactive Real-time Quiz Platform สำหรับห้องเรียนสด — อาจารย์สร้างข้อสอบ (มี AI ช่วยร่าง), นักเรียนเข้าสอบด้วยรหัส 6 หลักหรือ QR โดยไม่ต้องสมัครสมาชิก, อาจารย์เห็นทุกคำตอบแบบวินาทีต่อวินาที พร้อมระบบตรวจจับความสับสน (Confusion Detection) บันทึกพฤติกรรมการทำข้อสอบระดับคลิก และวิเคราะห์ผลด้วย AI (Local LLM ผ่าน Ollama) ทั้งระดับรายบุคคล รายห้อง และข้ามรอบสอบ

💾 โครงสร้างข้อมูล (4 Collections + Redis)

📄 Quiz quizzes

title · subject/chapter · difficulty · durationMinutes · hasTimeLimit · showAnswersAfterQuiz · status (draft/published/archived) · accessCode (6 ตัว, unique) · questions[] embedded (text, type MC/TF, imageUrl, choices[] + isCorrect) · emoji/gradient

👨‍🏫 Teacher teachers

name · email (unique) · passwordHash (bcrypt, ไม่ส่งออก JSON) · isActive · role · department

🏁 QuizSessionResult quizsessionresults

sessionId · quizId · sessionLabel (ชื่อรอบสอบ) · stats (avg/completion) · students[] (score, scorePercent, progress) · answers[] (isCorrect, responseTime, confusionLevel, changeCount) · questionStats[] pre-computed สำหรับกราฟ

🔬 QuizInteractionLog quizinteractionlogs

session_metadata · answer_logs[] ต่อข้อ: interactions[] (view / select / change / deselect / heartbeat + timestamp) · final_answer · is_correct · time_spent · is_confused · summary (score, confusion rate) — ออกแบบเป็น input ของ LLM

⚡ Redis (สถานะสดต่อ session · มี TTL)

meta: isPaused · isLocked · isTeacherLed · currentQuestionIndex · timer · startedAt  |  students: name, avatar (DiceBear), isOnline, score, progress  |  answers: finalAnswer, isCorrect, responseTime, history[] ทุกการเปลี่ยนคำตอบ, confusionLevel — จบสอบแล้วล้างทั้งหมด

⚡ ฟีเจอร์ทั้งหมด (พร้อม Data Flow & Use Case)

1) Teacher Authentication & Admin Management 🔐

FrontendBackendMongoDB

อาจารย์ล็อกอินด้วย email/password → ตรวจ bcrypt hash → ออก JWT แนบทุก request (middleware requireTeacher) · Super Admin มีหน้า /admin สร้าง/แก้ไข/ปิดใช้งานบัญชีอาจารย์ (soft-delete เก็บข้อมูลเดิมไว้)

Data Flow
Login Form→POST /api/auth/login→teachers (bcrypt verify)→JWT→เก็บ token ใช้ทุก request
Use Case: ภาควิชารับอาจารย์ใหม่ 3 ท่าน — แอดมินสร้างบัญชีให้ใช้งานได้ทันที ภายหลังมีอาจารย์ลาออกก็กดปิดใช้งานโดยควิซและผลสอบเดิมยังอยู่ครบ

2) Teacher Dashboard & Statistics 📊

FrontendBackendMongoDB

หน้า /teacher สรุปภาพรวม: จำนวนควิซแยกสถานะ, ผู้เข้าสอบสะสม, คะแนนเฉลี่ยถ่วงน้ำหนัก, กราฟ Weekly Performance ย้อนหลัง 8 สัปดาห์ (Recharts), Top Quizzes และ Activity Feed

Data Flow
Dashboard UI→GET /api/dashboard/stats→aggregate quizzes + quizsessionresults→Recharts render
Use Case: ต้นสัปดาห์อาจารย์เห็นคะแนนเฉลี่ยตกจาก 72% → 61% และควิซ "บทที่ 4" completion ต่ำสุด จึงวางแผนทบทวนบทนั้นก่อนสอนต่อ

3) Quiz Builder + AI Quiz Copilot ✍️🤖

FrontendBackendMongoDBOllama

สร้างข้อสอบ Multiple Choice / True-False กำหนดวิชา บท ความยาก เวลา เฉลย แนบรูปได้ทั้งคำถามและตัวเลือก ลากจัดลำดับ (dnd-kit) มี Preview Mode · AI Copilot: แชทสั่ง "ออกข้อสอบ 5 ข้อเรื่อง Python" — AI ตอบบล็อก json_quiz_update กดปุ่มเดียวเทลงฟอร์มทั้งชุด

Data Flow — บันทึกควิซ
Zustand Store→POST/PUT /api/quizzes (JWT)→quizzes  ·  รูปภาพ→Multer → /uploads
Data Flow — AI Copilot
AI Chat→POST /api/chat (Next.js)→Ollama (auto-detect model)→json_quiz_update → Apply ลง Builder
Use Case: อาจารย์มีเวลา 10 นาทีก่อนเข้าสอน — สั่ง AI ร่างข้อสอบ 5 ข้อ ตรวจแก้เฉลย 1 ข้อ เพิ่มรูป แล้ว Publish รับ Join Code ทันเวลา

4) Publish, Join Code & QR — การเข้าห้องสอบ 🎟️

FrontendBackendMongoDBRedis

Publish แล้วระบบสุ่ม Access Code 6 ตัวอักษร (ตัดตัวสับสน I/O/0/1, unique ทั้งระบบ) พร้อม QR และลิงก์ /play/{code} · นักเรียนกรอกแค่ชื่อ (avatar สุ่ม DiceBear) ไม่ต้องมีบัญชี · ครู regenerate code กลางคันได้

Data Flow
นักเรียน /play/[code]→GET /api/play/:code→โหลดโจทย์→Socket join_quiz→สร้าง session→ครูเห็น student_joined
Use Case: ครูฉาย QR บนสไลด์ นักเรียน 40 คนสแกนเข้าภายใน 1 นาที ชื่อทยอยเด้งบนแดชบอร์ด ครบแล้วครูกด Lock กันคนนอกเข้าเพิ่ม

5) Real-time Live Monitoring & Matrix Grid 📡

FrontendSocket.IORedisMongoDB

Matrix Grid: แถว = นักเรียน (progress + คะแนน), คอลัมน์ = ข้อสอบ, เซลล์ = สถานะ (🟩 ถูก / 🟥 ผิด / 🟨 กำลังทำ / ⬜ ยังไม่ถึง) คลิกเซลล์ดู ไทม์ไลน์การคลิกตอบทุกครั้ง · Live Leaderboard · Stats Panel · Answer Timeline Chart · รีเฟรชหน้าได้ไม่เสียข้อมูล (get_session_state กู้ snapshot จาก Redis)

Data Flow — ตอบ 1 ข้อ
นักเรียนคลิกตอบ→submit_answer→ตรวจเฉลยจริง→บันทึก + history + calcStats→broadcast answer_update→Grid ครูเปลี่ยนสีทันที
Use Case: ระหว่างสอบครูเห็นคอลัมน์ข้อ 7 แดงเกินครึ่งห้อง — กด Pause อธิบายเพิ่มหน้าชั้น แล้ว Resume ให้ทำต่อ ไม่ต้องรอตรวจหลังสอบ

6) Confusion Detection Engine 🧠

BackendRedis

ทุกคำตอบถูกประเมิน "ความสับสน" จาก จำนวนครั้งที่เปลี่ยนคำตอบ + เวลาที่ใช้: 🔴 High = เปลี่ยน ≥ 2 ครั้ง หรือ > 60 วิ · 🟡 Low = เปลี่ยน ≥ 1 ครั้ง หรือ > 30 วิ · ⚪ None — แสดงเป็น Badge ใน Grid, สะสมเป็น confusionCount ราย question และส่งต่อให้ AI วิเคราะห์

Use Case: นักเรียน A ตอบข้อ 3 "ถูก" แต่ขึ้น High Confusion (เปลี่ยนคำตอบ 4 รอบ) — ครูรู้ว่าน่าจะเดาถูก ไม่เข้าใจจริง จึงเรียกติวเพิ่ม ทั้งที่ระบบทั่วไปมองว่าผ่าน

7) Live Session Controller 🎛️

FrontendSocket.IORedisMongoDB

ครูสั่งผ่าน control_session: Pause/Resume (ล็อกการส่งคำตอบทั้งห้อง) · Lock/Unlock (ปิดรับคนใหม่) · Teacher-led Mode + set_question_index + set_timer (ทุกจอเลื่อนข้อพร้อมกันตามครู) · Reset Student รายคน · Regenerate Code · End + ตั้งชื่อรอบสอบ (sessionLabel)

Data Flow — End Session (Archive)
ครูกด End→ดึง snapshot เต็ม→คำนวณคะแนน + questionStats→QuizSessionResult→ลบ session→ล็อกจอนักเรียน
Use Case: สอบแบบ "ครูนำ" — เปิด Teacher-led เดินทีละข้อ ข้อละ 30 วิ ทุกคนเห็นข้อเดียวกันพร้อมกัน จบแล้วกด End ตั้ง label "ห้อง 2 - Midterm" ให้ค้นย้อนหลังง่าย

8) Student Result Screen 🏆

Frontend

จบข้อสุดท้าย UI เปลี่ยนเป็นหน้าสรุปทันที: ScoreCard (คะแนน %, ถูก/ผิด, เวลาเฉลี่ยต่อข้อ) + Answer Review List เฉลยรายข้อ (แสดงเมื่อครูเปิด showAnswersAfterQuiz) — พร้อมกันนั้นระบบส่ง Interaction Log ขึ้น Backend เบื้องหลัง

Use Case: นักเรียนเห็นทันทีว่าได้ 80% ผิดข้อ 4 กับ 9 เปิดเฉลยรู้ว่าตัวเองสับสนเรื่อง scope ของตัวแปร ก่อนออกจากห้องเรียน

9) Quiz Interaction Log System 🔬

FrontendBackendMongoDB

hook useQuizInteractionLog บันทึกทุกเหตุการณ์ต่อข้อ: view · select · change (from→to) · deselect · heartbeat (on_task/off_task) พร้อม timestamp — ส่งเป็น JSON ก้อนเดียวตอนทำเสร็จ Backend ตรวจคำตอบใหม่กับเฉลยจริงทุกข้อ ก่อนเก็บ

Data Flow
log in-memory ระหว่างสอบ→POST /api/quiz-logs (re-validate)→quizinteractionlogs→input ของ AI รายบุคคล

10) Personalized AI Analysis รายบุคคล 🤖🧑‍🎓

FrontendOllamaMongoDB

นำ Interaction Log มา build prompt (คะแนน, เวลา, confusion rate, flag "ตอบเร็วผิดปกติ/ลังเล" รายข้อ) ส่งให้ Ollama — ได้ผล 5 ส่วน: ประเมินภาพรวม / จุดแข็ง / จุดอ่อนที่ต้องทบทวน / แผนการเรียนเฉพาะคน / กำลังใจ — เลือกภาษา TH/EN/JA

Use Case: ขณะดู Session History ครูถามว่า "ข้อไหนควรเอาออกจากข้อสอบรอบหน้า" — AI ใช้สถิติบนหน้าจอตอบพร้อมเหตุผล

13) Cross-Session Comparison & AI Trends 🔁

FrontendBackendMongoDBOllama (SSE)

Use Case: สอน 3 ห้องด้วยควิซเดียวกัน — กราฟชี้ห้อง 2 ต่ำกว่าชัดเจน และ AI พบว่าข้อ recursion ผิดมากทุกห้อง (avg 31%) สรุปได้ว่าปัญหาอยู่ที่วิธีสอน ไม่ใช่ตัวห้อง
